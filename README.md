### Семантика

#### стратегия вычислений

- инструкции выполняются в строгом порядке указания
- выполнение последовательно с инкрементированием PC, так как ISA с RISC архитектурой предполагает фиксированные 32 битные команды, то шаг счётчика - 4 байта
- Последовательное исполнение модифицируемо с помощью команд условного и безусловного перехода
  - безусловные: 'jal' и 'jalr'
  - условные: 'beq', 'bne', 'blt', 'bge', 'bltu', 'ble'
- Последовательное исполнение может быть прервано аппаратно вызываемым прерыванием
    1. сохранить адрес возврата в `epc` регистр
    2. перейти на вектор обработки прерываний

#### области видимости

- Любая объявленная метка доступна из любой части кода
- метки в секции `.data` смещены на `0x10000`
- макросы и константы препроцессора (`%define`, `%macro`) доступны строго от места своего объявления и до конца файла (обрабатываются последовательно сверху вниз на этапе препроцессинга)

#### типизация, виды литералов

- в реализации типы данных отсутствуют, запись в памяти данных может быть интерпретирована как число или адрес
  - интерпретация числа как знакового или беззнакогого может происходить в АЛУ и ориентируется только на команду `blt` / `bltu`
- литералы
    1. целочисленные десятичные и целочисленные шестнадцатиричные литералы для прямой загрузки в I-type инструкциях, директивах
    2. строковые в формате C-строки, определяются диркетивой `.stirng "здесь_могла_быть_ваша_реклама\n"`
        - компилятор преобразует строку в последовательность байтов ASCII
        - escape-последовательности заменяются на ASCII код
        - каждый симовл - слово
        - в конце строки обязательно добавляется `0x00` терминатор размером с слово

#### макро-директивы

- препроцессор работает до начала трансляции и модифицирует исходный текст - `%define <name> <value>` задает константу, все вхождения которой ниже по коду заменяются на её значение
- `%macro <name>` и `%endmacro` позволяют определить многострочный блок кода. Вызов осуществляется указанием имени макроса. Внутри макросов также поддерживается подстановка констант, заданных через `%define`
- `%ifdef <name>`, `%ifndef <name>` и `%endif` управляют условной компиляцией: блоки кода внутри них будут включены в итоговую сборку только если константа `<name>` объявлена (или не объявлена)
- загрузка 32-битных адресов меток из секции `.data` в регистр, а также прямых значений в регистр осуществляется посредством двух директив-макросов препроцессора
	- `lui rd, $hi(label_or_num)`, `%hi(label_or_num)` - извлекает старшие 20 бит
	- `addi rd, rd, %lo(label_or_num)`, `%lo(label_or_num)` - извлекает младшие 12 бит

#### псевдоинструкции

- `j label`, транслируемая в `jal zero, label`
- `beqz rs, label` разворачивается в `beq rs, zero, label`

## Организация памяти

- размер машинного слова - 32 бита

### модель памяти

#### виды памяти и регистров

1. регистры общего назначения: 32 32-битных регистра, которые доступны для чтения и записи
    1. x0 (zero) — значение равно нулю, изменить значение - невозможно
    2. x1 (ra) — адрес возврата из процедур
    3. x2 (sp) — указатель стека
    4. t0-t6, s0-s11, a0-a7 - взяты из risc-iv, предназначение аналогичное
2. специальные регистры:
    1. PC — счетчик команд
    2. EPC — Exception Program Counter, используется для сохранения адреса при возникновении прерывания
3. память инструкций: начинается с нулевого адреса и не может редактироваться программой
4. память данных: логически отображается с адреса 0x10000 и может быть модифицирована из программы
    - транслятор считает, что секция `.text` начинается с `0x0000`, а секция `.data` — с `0x10000`. при запросе адреса переменной через макросы `%hi()` и `%lo()` транслятор возвращает значение адреса с учетом этого смещения
    - аппаратный контроллер памяти данных и кэш при получении запроса на чтение/запись перехватывает адрес. Если адрес >= `0x10000`, он аппаратно вычитает из него 0x10000 и обращается к физическому массиву байтов памяти данных, который начинается с нулевого индекса

#### хранение инструкций, процедур и прерываний

1. все инструкции и процедуры хранятся в секции .text, в памяти инструкций, точка входа в программу по умолчанию на `0x0000`
2. при возникновении прерывания, выполнение безусловно переходтит на адрес `0x0004` в памяти инструкций, где должна быть помещена инструкция безусловного перехода к обработчику прерываний

#### хранение статические и динамические данные

- статические данные хранятся в секции `.data` (память команд)
- динамические данные - стек, организуются программистом и хранятся в памяти данных

```scheme
        Registers
+-------------------------------+
| x0 (zero) : 0x00000000        |
| x1 (ra)   : return address    |
| x2 (sp)   : stack pointer     |
| ...                           |
| x31 (t6)  : temporary         |
| PC        : program counter   |
| EPC       : exception PC      |
+-------------------------------+

       Instruction Memory
+-------------------------------+
| 0x0000 : jmp N                |
| 0x0004 : interruption vector  |
|       ...                     |
| n      : program start        |
|       ...                     |
| isr    : interruption handler |
|       ...                     |
| proc1  : procedure            |
|       ...                     |
+-------------------------------+

          Data Memory
+-------------------------------+
| 0x10000 : num literals        |
|        ...                    |
| s+0     : string literals     |
|        ...                    |
| <sp>    : stack data          |
|        ...                    |
+-------------------------------+
```

#### кэширование

1. все обращения к памяти данных проходят через кэш
2. в системе реализован кэш прямого отображения, 8 линий по 1 слову
3. обращение в кэш занимает 1 такт, промах стоит 10 тактов
4. память инструкций опрашивается напрямую за такт

### варианты адресации

1. прямая загрузка операнда в I-type командах, операнд - часть инструкции. Пример `addi t0, zero, 42`
2. косвенная относительная:
    1. Адрес операнда вычисляется, как смещённое значение регистра source register. Пример `lw a0, 4(sp)` - загрузить слово по адресу sp + 4
    2. Адрес операнда вычисляется, как смещённое значение регистра `PC`. Пример `beq t0, t1, loop` - транслятор вычислит разницу в байтах между текущей командой и меткой `loop`
3. абсолютная адресация. Синтезируется вручную через загрузку старших 20 бит `lui` и прибавление младших 12 бит `addi`.

### механика отображения программы и данных на процессор

1. при обработке ассемблерного кода транслятор разделяет его на секции `.text` и `.data`
2. транслятор применяет макросы препроцессора`%define`, `%macro`, полностью заменяя их до начала генерации машинных кодов
3. транслятор создаёт единый бинарный файл, содержащий
  1. заголовок с метаинформацией
		1. отпечаток бинарника
		2. размеры секций
	2. скомпилированные машинные слова инструкций
	3. сырые байты данных
4. при инициализации процессор
	1. считывает бинарник
	2. парсит заголовок
	3. проверяет его отпечаток
	4. физически загружает инструкции в список text_mem, а данные — в data_mem.

### механика работы с данными и кодом во время исполнения

- поскольку языком программирования является ассемблер, транслятор не принимает решений по оптимизации памяти или распределению регистров, все решения явно описываются программистом, а транслятор и процессор реализуют заданную логику

#### литералы

- если числовое значение (литерал) помещается в 12 бит (от -2048 до +2047), оно не сохраняется в память данных. Во время компиляции транслятор встраивает его в 32-битное машинное слово инструкции (I-type, S-type, B-type). При исполнении процессор аппаратно извлекает его
- если литерал превышает разрядность регистров или является частью массива, необходимо явно объявить его в секции `.data` через директиву `.word`
- литералы в статической памяти укладываются последовательно согласно порядку в исходном коде. При этом каждое значение `.word` занимает ровно 4 байта.
- хранение строковых литерылов описано в разделе типизация, виды литералов
- литерал, требующий несколько машинных слов, разбивается на два 32-битных слова, и записывается подряд директивами `.word`. в памяти они займут 8 байт, порядок определяется нашей волей

#### константы

- в ассемблере нет разницы между константой и переменной на уровне памяти. константой считается блок данных в секции .data, который программа только читает (это зависит от автора кода программы)
- строковые константы (C-строки) объявляются директивой `.string "your_AD_here"`. Во время трансляции строка посимвольно в кодировке ASCII укладывается в память данных по слову на символ и обязательно завершается нуль-терминатором (0x00) - тоже словом

#### переменные

- предполагается, что автор программы самостоятельно решает назначить переменную в регистр, так как это гарантированный досутп без дополнительных тактов
- в случае нехватки регистров значения вытесняются в стек
- глобальные переменные (например флаги, адреса буферов, массивы для сортировки) объявляются в секции `.data` и находятся в памяти данных постоянно. Для работы с ними процессор сначала вычисляет их базовый адрес (`lui` + `addi`), а затем работает через команды (`lw`, `sw`). Размещение в память - воля программиста.

#### стек

- динамические локальные переменные, адреса возврата при вложенных вызовах и временные сохранения регистров записываются в стек. Стек представляет собой логическую область в памяти данных, адресация которой осуществляется косвенно через базовый регистр `sp`
- аппаратных команд для работы со стеком `push` / `pop` в архитектуре не предусмотрено. Регистр `sp` — это просто договоренность, необходимо вручную управлять памятью

#### инструкции

- во время компиляции `.text` преобразуется в массив 32 битных машинных слов, все метки вычисляются транслятором как смещения относительно `PC`
- по время исполнения модификация инструкций невозможна

#### процедуры

- во время компиляции процедура в данном случае просто метка в коде
- во время исполнения вызов процедуры осуществляется командой `jal ra, label`, которая меняет `PC` на адрес процедуры, а адрес следующей инструкции сохраняет в регистр `ra`.
- возврт из процедуры выполняется командой `jal zero, 0(ra)` - косвенный переход по адресу из `ra`
- если процедура вызывает другую процедуру, необходимо вручную сохранить значение `ra` в стек перед вызовом (вот так `sw ra, 0(sp)`) и восстановить его после, иначе адрес возврата будет перезаписан

#### прерывания

- с помощью механизма прерываний реализован ввод-вывод, контроллер ввода может асинхронно сигнализировать о наличии данных
- во время компиляции по зарезервированному адресу `0x0004` директивой `.org 0x04` помещается безусловный переход на обработчик прерываний
- - во время исполнения: если прерывания разрешены `ei` и наступило событие ввода interruption pending, текущая инструкция полностью завершает своё исполнение, но следующее значение `PC` помещается в регистр `EPC`, в `Control Unit` по обратной связи прерывания запрещаются, а следующий `PC` переписывается на `0x0004`
- обработчик читает данные из порта, инструкция `iret` в конце обработчика возвращает адрес из `EPC` обратно в `PC` и снова разрешает прерывания, возобновляя прерванную программу

## Система команд

### Особенности процессора

- процессор оперирует 32-битным машинным словом.
  - процессор оперирует 32-битными целыми числами (со знаком и без знака)
- размер любой инструкции строго фиксирован и равен 1 машинному слову
- устройство предполагает раздельные адресные пространства для инструкций и данных.
- программисту доступны 32 регистра общего назначения, в которые можно писать `register destination` и из которых можно читать `source register`, регистры `EPC` и `PC` используются неявно при выполнении кода в целом, при выполнении прерываний, условных и безусловных переходах, вызовах процедур и возвратах из них
- адресация:
  - способы адресации сильно ограничены
  - память данных доступна исключительно через инструкции для слов `lw`, `sw`
  - арифметические инструкции используют регистровую и непосредственную адресацию (прямая загрузка).
  - ветвления используют относительную адресацию (смещение от текущего `PC`).
- ввод-вывод изолирован от памяти и осуществляется через порты с помощью специальных инструкций `in` и `out`. Порт 1 используется для ввода, порт 0 — для вывода символов.
- поток управления изменяется условными (`beq`, `bne`, `blt`, `bge`, `bltu`, `ble`) и безусловными (`jal`, `jalr`) переходами.
- система ввода-вывода асинхронная и генерирует прерывания
  - управление прерываниями осуществляется командами `ei` Enable Interrupts и `di` Disable Interrupts
  - при возникновении прерывания текущая инструкция дорабатывает до конца, процессор сохраняет адрес следующей инструкции (которая должна была бы выполниться, если бы не произошло прерывание) в `EPC` и переходит по вектору `0x0004`
  - инструкция `iret` выполняет обратные действия - восстанавливает `PC` из `EPC` и автоматически разрешает прерывания

### Набор инструкций и их тактирование

- все команды выполняются за такт (за исключением оговоренных ниже случаев), так как Control Unit является комбинационной схемой, действия внутри такта разделены физическими задержками: подробно описано под схемой DataPath
- при обращении к памяти данные проходят через кэш
  - cache hit стоит накладных расходов на выставление адреса и защелкивание значения на выходе из кэша в начале следующего такта, поэтому добавляет 1 такт к выполнению
  - cache miss добавляет к времени выполнения жёстко заданный штраф в 10 тактов, связанный с задержкой работы памяти
    - при записи в память, запись идёт и в кэш и в память, поэтому запись всегда свзяана с накладной задержкой в 10 тактов

| Мнемоника                                                                  | Описание                                           | Формат | Кол-во тактов             |
| :------------------------------------------------------------------------- | :------------------------------------------------- | :----- | :------------------------ |
| `add`, `sub`, `mul`, `div`, `rem`, `and`, `or`, `xor`, `sll`, `srl`, `sra` | арифметические и логические (Register-to-Register) | R-type | 1                         |
| `addi`, `andi`, `ori`, `xori`                                              | арифметические и логические (Immediate)            | I-type | 1                         |
| `lw`                                                                  | чтение слова из памяти данных                | I-type | 1 + 1 (hit) или 10 (miss) |
| `sw`                                                                 | запись слова в память данных                 | S-type | 1 + 10                    |
| `lui`                                                                      | загрузка старших 20 бит константы в регистр        | U-type | 1                         |
| `beq`, `bne`, `blt`, `bge`, `bltu`, `ble`                                  | условное ветвление                                 | B-type | 1                         |
| `jal`                                                                      | безусловный переход с сохранением адреса возврата  | J-type | 1                         |
| `jalr`                                                                     | безусловный переход по адресу в регистре           | I-type | 1                         |
| `in rd, port`                                                              | чтение данных из порта ввода                       | I-type | 1                         |
| `out rs, port`                                                             | запись данных в порт вывода                        | S-type | 1                         |
| `ei`, `di`                                                                 | разрешение / запрет аппаратных прерываний          | I-type | 1                         |
| `iret`                                                                     | возврат из обработчика прерываний                  | I-type | 1                         |
| `halt`                                                                     | остановка процессора                               | I-type | 1                         |

### Кодирование инструкций

- кодирование бинарного представления машинного слова типизировано: инструкции собираются из полей
  - `opcode`: 7 бит, определяет базовый тип
  - `rd`: 5 бит, регистр назначения
  - `rs1`, `rs2`: 5 бит, регистры-источники
  - `funct3`: 3 бита, первое уточнение операции
  - `funct7`: 7 бит, для уточнения операции
  - `imm`: поле непосредственного значения

1. R-Type (регистровые операции)

- `add t0, t1, t2`

```word
31      25 24    20 19    15 14    12 11     7 6       0
+---------+--------+--------+--------+--------+--------+
| funct7  |  rs2   |  rs1   | funct3 |   rd   | opcode |
+---------+--------+--------+--------+--------+--------+
```

2. I-Type (операции с константой, `lw`, `jalr`, `in`)

- `addi a0, zero, 15`
- `lw a0, 4(sp)`
- `in rd, port` (`opcode = 0x73, funct3 = 2, imm = port`)

```word
31               20 19    15 14    12 11     7 6       0
+------------------+--------+--------+--------+--------+
|       imm        |  rs1   | funct3 |   rd   | opcode |
+------------------+--------+--------+--------+--------+
```

3. S-Type (`st`, `out`)  

- `imm` разбито на две части для сохранения позиции регистров `rs1` и `rs2`, как в R-Type
- `sw t0, 4(sp)`
- `out rs, port` (`opcode = 0x73, funct3 = 3, imm = port`)

```word
31      25 24    20 19    15 14    12 11     7 6       0
+---------+--------+--------+--------+--------+--------+
|imm[11:5]|  rs2   |  rs1   | funct3 |imm[4:0]| opcode |
+---------+--------+--------+--------+--------+--------+
```

4. B-Type (условные ветвления)

- структура аналогична S-Type, но биты смещения `imm` перетасованы для удобства знакового расширения.
- `beq t0, t1, offset`

```word
31      25 24    20 19    15 14    12 11     7 6       0
+---------+--------+--------+--------+--------+--------+
|i[12|10:5]|  rs2  |  rs1   | funct3 |i[4:1|11]| opcode|
+---------+--------+--------+--------+--------+--------+
```

5. U-Type (загрузка старших бит константы)

- `lui t0, 0x10000`

```word
31                                12 11     7 6       0
+-----------------------------------+--------+--------+
|             imm[31:12]            |   rd   | opcode |
+-----------------------------------+--------+--------+
```

6. J-Type (безусловный переход со смещением)

- биты смещения перемешаны аппаратно
- `jal ra, offset`

```word
31                                12 11     7 6       0
+-----------------------------------+--------+--------+
|       imm[20 | 10:1 | 11 | 19:12] |   rd   | opcode |
+-----------------------------------+--------+--------+
```

## Транслятор

### интерфейс командной строки

- командf для запуска

```bash
python translator.py <input_file> <output_file> [--log <log_file>]
```

- входные данные:
  - `input_file` - путь к текстовому файлу с исходным кодом. Обязательный позиционный
  - `output_file` - путь, по которому будет сохранен собранный машинный код. Обязательный позиционный
  - `--log <log_file>` - путь для сохранения отладочного журнала. По умолчанию: `program_dump.log`, необязательный именованый
- выходные данные:
  - бинарный файл машинного кода по пути <output_file>
  - в консоль выводится подтверждение об успешной компиляции и имена сгенерированных файлов

### принцип работы транслятора

1. препроцессинг (`Translator._preprocess`)
    1. удаление комментариев (всё, что следует за символом `;`) и пустых строк
    2. если метка и инструкция находятся на одной строке, они принудительно разделяются: метка всегда обрабатывается как отдельный логический элемент
    3. обработка директив препроцессора (выполняется сверху вниз):
	    - сбор констант (`%define`) и их применение к последующему коду
	    - разрешение блоков условной компиляции (`%ifdef`, `%ifndef`, `%endif`), код внутри отключенных блоков удаляется
	    - регистрация макросов (`%macro`, `%endmacro`). При встрече имени макроса в коде, оно заменяется на тело макроса, при этом внутри тела также происходит подстановка актуальных констант `%define`
2. первый проход (`Translator._first_pass`)
    1. транслятор проходит по всем строкам и отслеживает текущий адрес для инструкций и данных: при этом счетчики адресов для `.text` и `.data` независимы, и память команд начинается с адреса `0x0000`, а память данных смещена на `0x10000`
    2. директива `.org` позволяет задавать смещение внутри текущей секции
    3. при обнаружении метки её текущий вычисленный адрес сохраняется в таблицу `self.labels`
    4. для данных высчитывается размер: `.word` занимает по 4 байта на элемент, `.string` — длину строки * 4 байта + 4 байта на нуль-терминатор
3. второй проход (`Translator._second_pass`)
    1. транслятор преобразует каждую инструкцию в 32-битное слово (число ЯП, бин представление которого - машинное слово)
        1. парсинг мнемоники и операндов
        2. замена имен регистров на номера (`Translator._get_reg`)
        3. превращение immediate values в числа (`Translator._resolve_imm`)
          - операнды вида %hi(label) и %lo(label) высчитывают старшие 20 бит и младшие 12 бит адреса метки из секции данных.
          - метки заменяются на абсолютные адреса (для псевдоинструкций или макросов) или на относительные смещения (разница между адресом метки и текущим `PC` для команд ветвления B type и J type)
        4. вызов с полученными аргументами функций кодирования соответствующего типа (R, I, S, B, U, J).
    2. транслятор автоматически разворачивает псевдоинструкции: `j offset` превращается в `jal zero, offset`, а `beqz rs, offset` — в `beq rs, zero, offset`
    3. директивы данных конвертируются в байтовые массивы (Little-Endian), C-строки явно завершаются `0x00`
    4. формируется человекочитаемый лог в формате `<address> - <HEXCODE> - <mnemonic>`
4. формирование бинарного файла (`Translator._build_binary`)
    1. запись заголовка из 12 байт:
        1. отпечаток для верификации файла
        2. размер секции кода в байтах
        3. размер секции данных в байтах
    2. тело:
        1. строки секции .text из чисел ЯП переводятся в байты и пишутся в бинарник
        2. байты секции .data пишутся из массива байт

## Модель процессора

### DataPath

![DataPath](/DataPath.drawio.png)

#### поэтапное описание

##### Instruction Fetch

1. по сигналу такта PC защёлкивается и указывает на адрес в Instruction Memory
2. Память выставляет 32 битную инструкцию

##### Decode

3. PC передаётся на на входы двух сумматоров (ветвление и прямой переход)
	- отдельные биты ([19:15] rs1, [24:20] rs2, [11:7] rd) идут на Register file и выставляют номера регистров-источников, регистра назначения. Ложная запись предотвращается отсутствием сигнала на запись и записью по такту
	- для получения Imm значения Imm_Generator требует op [6:0], func3 [14:12], imm (полное покрытие [31:7]), при этом imm для разных команд может быть перемешан и сложно упакован в команде, поэтому фактически блок обработки операнда, переданного в теле команды, принимает команду целиком!
	- отдельные биты (op, func3, func7, imm) идут на Control Unit для выставления управляющих сигналов мультиплексоров и устройств
4. Далее по выставленным данным блоки осуществляют следующие действия
	- Control Unit выставляет управляющие сигналы команды в DataPath
	- Reg File выставляет на выходах значения регистров-источников
	- Imm Generator обрабатывает и собирает операнд прямой загрузки

##### Execute

- мультиплексоры перед АЛУ, управляемые Control Unit, выбирают операнды: на один вход всегда идет `rs1`, на второй — либо `rs2`, либо сгенерированная константа из `Imm_Generator` (сигнал `ALUSrc`)
- АЛУ выполняет арифметическую, логическую операцию или вычисляет адрес для памяти
- `Branch Unit` сравнивает значения регистров. Если условие ветвления (сигнал `BranchOp`) совпадает с флагами АЛУ, генерируется сигнал `Cond`, Мультиплексор перед сумматором PC + imm\4 выбирает этот Imm, если сигнал `Cond` равен True и вычисляет целевой адрес ветвления (`PC + Imm`).

##### Memory

- вычисленный в АЛУ адрес подается на адресный вход кэша:
	1. если выставлен сигнал `MemRd` (чтение `lw`) или `MemWr` (запись `sw`), кэш проверяет наличие нужного тега
	2. при Cache Hit данные читаются за 1 такт и передаются дальше на мультиплексор записи
	3. при Cache Miss контроллер памяти выставляет сигнал `Stall`
	4. Control Unit получает этот сигнал и  обнуляет сигналы `PcWr`, `RegWr` и `MemWr` , пока кэш подтягивает данные из `Data Memory`, после подтягивания сигнал Stall перестаёт подаваться памятью
- происходит работа с портами ввода-вывода (I/O Module), если поступила команда `in` / `out`.

##### WriteBack

1. данные готовы к записи по фронту следующего такта
	- итоговое значение из памяти, портов, АЛУ или `PC+4` доходит до входа данных регистрового файла, селектор выставил нужные данные на вход регистрового файла
	- мультиплексор, управляемый сигналом `SelPC`, вычисляет базовый адрес следующей инструкции: `PC+4`, ветвление или адрес из регистра - это значение подается на вход данных регистра `EPC` для сохранения адреса возврата при прерывании
	- перед входом в регистр `PC` стоит ещё один мультиплексор, управляемый сигналом `Int` от `Control Unit`, который при отсутствии сигнала `Int` пропускает базовый адрес, но уводит поток выполнения на вектор `0x0004`, если произошло прерывание
2. По фронту следующего такта происходит физическое обновление `PC` и целевого регистра `rd`, защёлкивание памяти завязано на её внутреннем устройстве

#### отдельные элементы DataPath

##### Контроллер ввода-вывода (I/O Module)

1. ввод-вывод в системе реализован как port-mapped I/O с системой прерываний
2. модуль ввода-вывода подключен к DataPath
  1. входы - шина данных и портов
  2. выход - считанное значение
3. модуль ввода-вывода подключен к Control Unit - сигнал запроса прерываний `IntPending`
4. адресация портов:
  1. порт 1 — используется для ввода данных
  2. порт 0 используется для вывода данных
2. логика ввода
  1. заранее задано расписание: массив пар `(такт, символ)`
  2. как только счетчик тактов процессора достигает времени наступления события, I/O модуль сохраняет ASCII-код символа в свой внутренний регистр и выставляет аппаратный сигнал `IntPending`, который уходит в Control Unit
  3. внутри обработчика прерываний процессор выполняет инструкцию `in rd, 1`, а модуль ввода-вывода отдаёт данные на шину и сбрасывает свой внутренний флаг `interrupt_pending` по сигналу `PortRd`
  4. pending будет висеть, пока не произойдёт чтение, но сам символ может быть затёрт следюущим, потому что буфер ввода - один регистр
3. логика вывода
    - осуществляется синхронно при выполнении инструкции `out rs, 0`.
    - I/O модуль принимает 32-битное значение с шины `REG_B`, выделяет из него младшие 8 бит и отправляет их в буфер вывода

### ControlUnit

![ControlUnit](/ControlUnit.drawio.png)

1. обработка Stall и Halt:
  1. в архитектуре предусмотрены ситуации, когда состояние процессора не должно меняться. Это происходит либо при команде `halt`, либо когда кэш памяти данных не успел загрузить информацию и выставляет сигнал `Stall`  
  2. если так, управляющий сигнал переключает мультиплексор, который принудительно заменяет все сигналы записи (`RegWr`, `MemWr`, `PcWr`, `PortWr`) на нули. 
  3. счетчик команд не растет, память и регистры не перезаписываются, пока кэш не снимет сигнал `Stall`. остальные сигналы (например, `MemRd`) продолжают поступать в DataPath, позволяя кэшу завершить чтение.
2. обработка прерываниями в составе блока управления
	1. внутри схемы находится D-триггер Interrupt Enable `IE`, хранящий статус разрешения прерываний
  2. сигнал прерывания `Int` подаётся, если выдаётся, если `IE=1` && есть внешний запрос от I/O `InptPending`
	2. `Int` в DataPath выполняет две функции
    1. переключает финальный мультиплексор перед `PC` на вектор `0x0004`
    2. служит сигналом для защелкивания адреса следующей инструкции в `EPC`
	3. cигнал `Int` также сбрасывает триггер `IE`, выбирая 0 на мультиплекторе перед вход `IE`. Если нет прерывания, то на запись подано разрешение или запрещение прерываний IntEnData
  4. Запись в `IE` разрешается, если 
    1. нет stall или halt
    2. подана команда изменения разрешения прерываний или сигнал прерывания `Int`
